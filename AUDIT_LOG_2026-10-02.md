## Závěr

Stav: **PODMÍNĚNĚ – po opravách je logika výrazně bezpečnější, ale před označením systému za plně ověřený je nutný nový produkční běh Windows agenta nad aktuálním main.**

Důvod: poslední dostupný produkční snapshot před aktuálními opravami stále obsahoval VIN WF04XXWPG4GR04000 jako CHYBÍ POJIŠTĚNÍ. Tento snapshot je starší než opravy prodeje a nelze jej použít jako potvrzení nové logiky.

## Autoritativní rozhodovací pravidlo

1. SQL/TIRBazar určí, zda vozidlo MÁ BÝT POJIŠTĚNO nebo NEMÁ BÝT POJIŠTĚNO.
2. MÁ BÝT POJIŠTĚNO:
   - UNIQA ano nebo Allianz ano = OK.
   - UNIQA ne a Allianz ne, oba zdroje dostupné = CHYBÍ POJIŠTĚNÍ.
   - potřebný zdroj nedostupný a pojištění není potvrzeno druhým zdrojem = NELZE OVĚŘIT.
3. NEMÁ BÝT POJIŠTĚNO (prodej, vykoupené+depozit, nepřítomné s výkupem):
   - nalezeno v UNIQA nebo Allianz = chyba / vyžaduje kontrolu.
   - nenalezeno v obou a oba zdroje dostupné = správně nepojištěno.
   - některý zdroj nedostupný a pojištění nebylo nalezeno = NELZE OVĚŘIT.
4. Prodej je prvotní kritérium. DatumProdeje nebo stav PRODANÉ znamená očekávání NEPOJIŠTĚNO; výjimka je explicitní prodej Vans Renting.
5. DEPOZIT se vyhodnocuje pouze u aktuálně VYKOUPENÉHO vozidla.

## Bezpečnost – otevřený kritický bod

cloud_agent.py obsahuje synchronizační token jako hardcoded fallback. To je bezpečnostní dluh a hodnota existuje i v Git historii.
Pokus o okamžité odstranění byl vrácen, protože Windows agent dnes nemá tento token uložený v bezpečném credential store a po restartu by se odpojil.

Nutná následná oprava:
1. zavést bezpečné uložení DENNI_POV_SYNC_TOKEN na Windows,
2. vygenerovat nový token,
3. nastavit nový token na Renderu a Windows,
4. odstranit fallback z kódu,
5. starý token zneplatnit,
6. podle citlivosti zvážit přepsání Git historie.

Tento bod je **NEVYŘEŠENÝ** a nebrání správnosti samotného POV porovnání, ale brání označení repository security za čistou.
